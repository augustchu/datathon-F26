# How we supplemented and verified the facility data

The evidence workbook, the sampled reviews and the bed predictions answer three different questions. The workbook records **where published values disagree**. The reviews check **which value the available evidence supports**. The capacity models estimate **a count where the eligible facility still has no documented value**. The original Virtue Foundation facility data, called FDR in the code, is preserved throughout. [Supplement build guide](README.md)

## 1. We started by looking for sources that could corroborate FDR

The competition asks us to cite the evidence for a recommendation. We looked for independent directories and public lists that contained useful fields such as a facility's name, contact details, address, services and validity period. At this point we discussed a per-source random audit at **95% confidence with ±5 percentage points**. The first question was whether the scraper copied the page correctly. A separate cross-source phase would have tested corroboration. We paused the larger audit after initial browser spot checks. The small checks produced no completed 95% validity estimate. [Source collection and sampling history](../ACTION_LOG.md#statistical-validation-requested)

Later we discussed screening new sources with an **80% confidence** hypothesis test before using them. We then simplified that proposal to cross-checking the existing claims and manually checking conflicting values. The 80% screen was a proposed design. It supplied neither a completed test nor a sample size for the workbook. A check that faithfully copies a webpage tells us what that publisher said. Independent corroboration, the exact branch, the count definition and the reporting date determine what we can conclude about the facility. [Dead-end and cross-check rationale](../non-ml/DATA_COMPARISON.md#dead-end-for-capacity-verification-using-the-saved-government-extracts)

## 2. We recovered facts already present in text and tested a small public-source pilot

Before guessing missing bed counts, we checked whether the description already stated them. The description experiment recovered 12 previously blank counts. Nine belonged to the training partition. The label-source description stayed outside the model inputs for that experiment. It gave us a small set of attributable values, with little consistent improvement in prediction error. [Description recovery experiment](../ML/MODEL_EVALUATION.md#using-counts-recovered-from-descriptions)

We implemented a separate source-recovery pipeline for explicit bed counts, doctor counts, equipment and named services. Beautiful Soup extracted exact passages from selected public facility pages. The browser check confirmed the passage, facility address and scope. Faridabad Medical Center's page supplied a 35-bed total and a separate NICU statement. Arti Hospital's shared footer and group page could not establish dialysis or a 103-bed total for the specific Budge Budge branch. That led us to require a branch anchor alongside the claim and to hold ambiguous statements. [Source-recovery implementation](../non-ml/SOURCE_GROUNDED_FIELD_RECOVERY.md) · [Browser checks and screenshots](../data/recovery/SAMPLING.md)

## 3. We changed sources when the government extracts lacked comparable counts

The saved government empanelment extracts remained useful for addresses, contacts and listed services. Their saved schema had no whole-facility bed field, so we shelved them for checking bed labels. The next pass used IFFCO Tokio's 2025 HTML disclosure and SBI General's 2022 PDF for whole-facility bed and doctor counts. We also tested Delhi's approved beds and Kerala's sanctioned inpatient beds. Those figures stayed in their own scope. A licensed or sanctioned count, a department count, a historical milestone and a whole-branch total describe different things. [Government extract comparison](../non-ml/DATA_COMPARISON.md#dead-end-for-capacity-verification-using-the-saved-government-extracts) · [Count sources and scope](../data/recovery/capacity-evidence/README.md)

The accepted count matches used a unique normalized facility name and matching PIN. Ambiguous names, alternate branches and conflicting locations went to the identity queue. The workbook preserved the original value, other claims, dates and URLs. Excluding publishers already cited for the FDR branch left outside count candidates for **347 branches with missing beds** and **270 with missing doctor counts**. These were source-reported observations. Some are historical and both insurers may have obtained figures from the same hospital. The wider audit also retained staffing, ICU, equipment, websites, accreditation, services and establishment-year evidence with its own scope. [Coverage and linkage](../data/recovery/capacity-evidence/README.md#coverage-on-the-saved-virtue-foundation-audit)

## 4. We built the workbook and set a review budget

The **Manual check list** had **493 outstanding value comparisons** when exported. The unit is a facility and a field, so a hospital can appear for both beds and doctors. Multiple claims for the same facility and field were grouped. The original export counted **210 bed**, **263 doctor**, **19 website** and **1 establishment-year** comparison. Another **3,265 facility–field leads** required branch identification and stayed in the supporting tabs. Two early bed reviews were already recorded. Holy Family Hospital's page supported the Bandra count of 268. Shri Balaji Metro Hospital's expansion approval and conflicting operating figures left its exact total unresolved. The workbook is a snapshot from before the later pilots, so use the review ledgers when deciding which rows remain pending. [Original queue and early checks](../data/recovery/capacity-evidence/README.md#browser-adjudications)

We did discuss how many to review. The **50-case threshold** came from your instruction to queue the list when it exceeded 50. The later request for a reasonable training sample led to an initial 36 and then an extension to 48, with priority on sparse fields that matter for facility scale. The threshold was a time and effort decision. The number of resolved cases needed to compare selectors reliably depends on how often comparable evidence is found and what difference we want to measure. [Frozen sampling code](src/sample_manual_checks.py)

## 5. We ran two separate source-selection pilots

| Pilot | Facility–field cases | Exact whole-facility counts supported |
| --- | --- | --- |
| Iteration 01 | 16 bed, 14 doctor, 5 website and 1 establishment year | 5 bed, 0 doctor |
| Iteration 02 | The original 36 plus 6 bed and 6 doctor cases | 7 bed, 0 doctor |

The count samples drew from IFFCO-only, SBI-only and both-insurer groups. We froze the order by a hash of the facility and field. The extension added two count cases per group per field. Only an exact, comparable reference gave a training label. Each candidate got a positive label if it matched, or a negative label if an exact reference supported a different value. Inconclusive cases supplied no label. Doctor directories, rounded counts and staffing subsets explained several of the doctor abstentions. [Iteration 01 results](iterations/01-pilot.md) · [Iteration 02 results](iterations/02-extension.md)

This XGBoost **source selector** chooses among existing claims. Both bed selectors tied the pooled publisher rule on exact choices and had too few supported cases to clear the release gate. No doctor selector could be fit. We used the publisher fallback for eligible claims in both frozen supplements and saved the experimental model choices separately. Direct review takes precedence. A manually unresolved count is blank, an identity hold blocks automatic filling, and a still-pending conflict can retain a contested source value with provenance. The publisher fallback is a practical default based on a small sample. It cannot establish which insurer is generally more accurate. [Release rules](README.md#dataset-decisions-and-provenance) · [Selector evaluation](experiments/source_selection/README.md)

## 6. We tried In The Loop on a separate test sample

We froze nine new bed disputes, three per source group, and reused Holy Family as an earlier reference. Codex checked the public branch evidence and recorded the decisions in In The Loop. **Ten branch cases produced 20 candidate rows** because a branch can have multiple claims. The app recorded **2 accepted, 2 rejected and 16 inconclusive** rows. Only two branches had a public exact count that could be scored. In both, the selectors and publisher rule matched the operator's assertion. Those operator pages give no observation date. This establishes agreement with those two publications, with most disputes still unresolved. [Review receipts, screenshots and replay](experiments/verification/README.md)

The rest of the workbook **can** use In The Loop. The workbook itself has source links, while the app needs a screenshot reference on every review row. Prepare a small CSV with a stable case ID, branch and PIN, field, candidate count and publisher, date and scope, source URL and screenshot path. Add one row per claim when there are competing values. Capture the public evidence that can resolve the comparison and attach it locally. Reviewers can export their decisions and notes, which can then be reconciled by case ID into a new evidence ledger. A matching screenshot can establish what the page says. Accept a correction only if it also establishes the same branch and comparable count. Keep inconclusive claims unresolved. [Spreadsheet and screenshot import instructions](../In%20The%20Loop%20Verification%20Tool/README.md#prepare-a-spreadsheet)

For the next audit we proposed **12 new facility–field cases** after excluding earlier reviews. Six would be bed counts and six would be doctor counts, with two per insurer group in each field. This would measure the kinds of errors and ambiguities the review could find within a small work budget. Estimating accuracy across all 493 comparisons would require a separate sample design. [Targeted verification proposal](../possible-next-steps/03-targeted-verification/README.md)

## 7. We finished the separate XGBoost bed-count comparison

The second type of XGBoost model predicts a number for an eligible facility whose bed total is still missing. The completed comparison has **six fitted regressors**, from two frozen supplements crossed with facilities only, facilities plus NFHS socioeconomic data, and facilities plus NFHS and district population. The two supplements supplied iteration-specific filled doctor inputs and training labels. The six models shared **456 test facilities and the same original reported bed targets**, with **213 separate facilities for tuning and 213 for interval calibration**. This makes the test scores comparable even though the training data differ. The final rerun held out all ten In The Loop review branches. Six had been in the earlier training set, and the other four were already outside the evaluation cohort. We excluded the mislabeled 200,000-bed entry and kept descriptions that can state beds and previously predicted counts out of the regression features. [Full training design and results](experiments/capacity/RESULTS.md)

Iteration 01 with NFHS and population had the lowest test MAE, **136.49 beds**, compared with **160.78** for the training-median baseline. It beat the matching NFHS model by **0.10 beds**, with a paired 95% interval consistent with either model doing slightly better. The facilities-only iteration 01 model led on validation. The selected model substantially underpredicted large facilities, and the population input is a district total with a user-confirmed row-order join. It does not contain a land-area denominator for density. The test result was used to choose the export model, so independent evaluation of that choice would need fresh labels. [Evaluation and population caveats](experiments/capacity/RESULTS.md#why-we-used-this-model)

The standalone export preserved 10,088 original rows and estimated capacity for **6,829 eligible branches**. Estimates carry their own status and interval. They describe facility scale, with current occupancy and service availability requiring separate evidence. The local W&B receipt records 11 completed runs across verification, source selection and capacity modeling. [Export contract](experiments/capacity/RESULTS.md#final-export-contract)

**Why keep this run?** It answers the agreed six-way comparison with fixed test facilities, separate tuning and a recorded export rule. Repeating it on the same inputs adds no independent evidence. Choosing new settings after looking at those test results would make the comparison less informative. A new run would make sense with substantially better adjudicated counts, a checked population or density crosswalk, or a fresh evaluation set for facilities whose original counts were missing. Preserve the completed run as the baseline for any of those changes.

## 8. We reviewed 12 more cases for scraping errors

We froze six bed disputes and six doctor disputes across IFFCO-only, SBI-only and differing dual-insurer claims. We checked the saved IFFCO HTML table and SBI PDF against the 16 extracted insurer values, then recorded one result per facility and field in In The Loop. Every insurer value matched its source. These are targeted results for the audited claims. They leave the broader extraction error rate and the accuracy of the underlying FDR fields unmeasured. ### How to carry these outcomes into the next dataset version

- **Seven disagreements.** Keep every published value with its reporting date, count definition, branch, source link and review ID. Start with the selected comparison field unresolved. Promote a count to `direct_review` only when the evidence supports an exact value for the intended reporting period and definition. For example, the state board's account of Sanjiban Hospital supports a historical 500-bed claim, while SBI's March 2022 report lists 100. Both can remain in the history. A newer date alone or an average would supply no adjudicated total. [State board record](https://www.wbpcb.gov.in/files/Fr-06-2023-06-15-28Sanjiban%20Hospital%20%28%20A%20unit%20of%20Chikitsabrati%20Udyog%29.pdf)
- **Five unclear cases.** Preserve the raw figures and mark the affected selected field `review_unresolved`. Leave it blank until evidence resolves the issue. Shreya Hospital needs the Kengeri versus Harihar attribution checked. Apply a branch or routing hold if the underlying facility identity or destination also remains uncertain. For the four doctor cases, keep the hold specific to the count when the branch is otherwise known. At Kirti Hospital, one clinician in a clinic directory provides evidence about that listing. An exact whole-branch doctor total needs an administrative roster or an equivalent source with a definition and date. [Kirti facility record](https://ipc.gov.in/images/1050_AMC_Details_As_on_date_27.05.2025.pdf) · [Proposed Hindi call pilot](../non-ml/MASS_VERIFICATION.md#proposed-next-step-after-the-browser-review)

Keep these as field-review decisions for a new evidence snapshot. App acceptance records the observed disagreement. A source-selector label requires an adjudicated reference value. The two saved source selectors still use the existing publisher fallback for release, and an unresolved field belongs in the review path ahead of that fallback. ### What the existing models actually did

Both frozen supplements still carry the original FDR count for all 12 audited fields. Ten have `fdr_reported_contested`, while two bed counts look like `fdr_reported` because the supplement excludes insurer claims from publishers already cited by FDR. The exclusion avoids double-counting a publisher. The separately audited disagreement still matters for the field's quality. The saved trainer used **three audited bed counts as training targets** and **five audited doctor counts as predictors** in each of the six fits. None of the 12 branches is in the common test set or calibration cohorts. [Supplement selection](src/build_dataset.py) · [Train and evaluation eligibility](experiments/capacity/prepare_data.py) · [Fitting and missing-value handling](experiments/capacity/train_evaluate.py)

The pipeline already handles an explicit unresolved decision in useful ways. A held bed count stays blank and out of target training, evaluation and automatic imputation. A held doctor count can flow to XGBoost as a missing predictor, so a branch with an otherwise valid bed label can still be used. Today a contested bed value can enter training and a contested doctor value can enter the numeric feature matrix. The models cannot infer from those numbers that their evidence is disputed. Record the review once in the offline dataset builder and enforce field-level eligibility there. These checks were read-only against the completed training inputs and outputs. The audit changed only this document.

## 9. We built the reviewed dataset version and checked what retraining needs

The updated builder compares exact branch-linked whole-facility counts before applying the publisher-overlap filter. It keeps all branch-linked count claims in `external_count_history`, including licensed or approved counts with their own scope. `eligible_external_claims` carries the claims that can inform the source selector or fallback. A numeric disagreement across publication dates is an audit flag. An explicit unresolved field review suppresses that selected value. The flat CSV exposes a separate disagreement flag for beds and doctors. Each optional field review matches an exact name and PIN, records its evidence and rationale, and takes precedence over the stored publisher choice for that field. [Dataset builder](src/build_dataset.py) · [Twelve review decisions](field-reviews/scrape-audit-12.json)

Both new supplements in `local/count-review-refresh-v1` preserved all **10,088 original rows** and their routing, service and contact records. Each supplement now has **six held bed counts and six held doctor counts** from this audit. The code also surfaced **11 previously ordinary FDR fields** with discrepancies involving an already cited publisher, including two from the 12-case audit. Eleven counts unique branch–field pairs across either supplement. For each reviewed doctor field, the raw value remains traceable, the modeling input is blank, and the bed decision is preserved. In the prepared model inputs, training targets fell from **1,616 to 1,613** for iteration 01 and **1,613 to 1,610** for iteration 02. Both retain the same 426 calibration and 456 test branches. Only the preparation steps were run. [Field review validation](src/validate_run.py) · [Prepared input receipt](local/count-review-refresh-v1/inputs/input_audit.json)

### Checks to settle before fitting again

1. **Fix the known extraction omission and freeze the source version.** In the separate fidelity audit, IFFCO printed `04` doctors for Suraksha Hospital and the parser emitted a blank. Fix the integer rule, replay against the same saved file and diff the extracted counts and branch joins. The 12-case audit measured disagreements after extraction and did not test recall. [Scraper fidelity findings](experiments/verification/scraper-audit/README.md)
2. **Get adjudicated labels for source selection.** The two saved selectors trained on five and seven supported bed cases respectively. There are zero exact doctor reference totals in the pilot. A useful next sample includes same-branch, same-scope disputes with independent dated evidence, and cases where no supplied candidate matches. Reserve an independent branch-level test before fitting and keep unclear cases as abstentions. Compare both selector recipes with the publisher fallback and assess exact matches, error in beds or doctors, and how often each can make a selection. [Source-selector evaluation](experiments/source_selection/README.md)
3. **Verify which source policy made each capacity input.** The prior six regressions compared two supplements released using the publisher fallback. For the next comparison, generate a versioned output from each selector, then build the same three feature tiers for each output. Keep a fallback control and count the branch–field choices that actually differ before attributing any result to source selection. Keep the capacity test branches out of selector fitting. If the selector supplies experimental choices for branches that also provided its review labels, use out-of-fold choices for those rows. Use the same held-out capacity targets in all six regressions. The existing population file contains district population and lacks an area denominator. Confirm its geography and vintage or use a keyed population-density input if density is the intended feature. [Previous capacity design](experiments/capacity/RESULTS.md)
4. **Agree on model selection and the pipeline file.** Use MAE in beds as the primary comparison, with large-hospital error and interval coverage as practical checks. Choose on validation and report on a fresh held-out set where feasible. The previous test already selected an export model. For the pipeline, use one estimate per canonical `facility_id` and pass the estimate, interval and model provenance in notebook 05's estimate format. The analysis spreadsheet can still show every original row. The dashboard's load-balancing rank uses occupancy data. Estimated bed capacity can describe facility scale, and using it to estimate occupancy would need a separate measured or explicitly labeled scenario input.
