# Feedforward source-rule evaluation

**The weighted blends did not beat the best individual rule on the 455 shared held-out facilities.** The fixed blend selected on development averaged **136.81 beds** of absolute error. The feedforward blend averaged **136.96**. Publisher ranking with district population averaged **136.44** using the same feature tier. Against that individual rule, the fixed blend was 0.38 beds worse and the network was 0.53 beds worse. Both paired 95% intervals include zero. The earlier best from all feature tiers was 134.99 beds, from a date-based rule with NFHS socioeconomic features. [Earlier rule comparison](RULE_CLEANING_COMPARISON.md) · [Notebook](../../../ML/notebooks/Source%20Rule%20Feedforward%20Ensemble.ipynb)

## What ran on November 21, 2026

1. **Freeze the comparison.** The notebook used the `population` feature tier, which combines facility features with district population totals. It checked the two input file hashes and the validation, calibration and test cohort fingerprints against `rule-cleaning-v2`. The test denominator and reported bed labels match the earlier comparison exactly. Four cleaning rules supplied two distinct model outputs. The newest-source, same-year average and two-year average had identical model inputs and predictions, so the network gave them one shared input. Counting each alias separately would have given that same output three votes.
2. **Generate training predictions.** Five district-grouped folds fit two XGBoost boosters each. Each fold left out the test fold’s entire districts, including supplementary labels from those districts, and fitted its encoding on the remaining rows. The notebook reused the archived depth, objective and stopping round for each rule. This gave 1,284 out-of-fold estimates scored against reported bed counts from the original training partition. The separate historical test and interval calibration partitions supplied no network-training examples.
3. **Fit the weighting methods.** A district-grouped split put 1,075 out-of-fold estimates into blend fitting and 209 into development. An eight-unit hidden layer used log-transformed base predictions and their disagreement to assign weights. A softmax kept the weights nonnegative and summing to one. Mean absolute error in beds was the loss. The network’s best development checkpoint was epoch 6. Development MAE selected the fixed blend before test. Its weights were approximately 50% publisher ranked and 50% for the shared date-based prediction. The neural network averaged 51.16% and 48.84% respectively on test. The fixed and equal blends differed by one rounded prediction among the 455 test cases.
4. **Check the held-out comparison.** The archived population boosters reproduced the saved row-level predictions exactly. The scoring run rechecked facility IDs and reported capacities for each reference. The 213 calibration rows set interval widths. The final 455 were used for test MAE, RMSE, paired differences and interval coverage. Uncertainty in MAE differences comes from 1,500 paired bootstrap resamples of the 212 test clusters. The interval compares errors on the same rows. These historic labels have been used in earlier project evaluations and can contain reporting error. Coverage on reported facilities does not establish coverage for facilities whose capacity is genuinely missing.
5. **Record the final execution.** All six code cells ran in **3.44 seconds** on the local arm64 Mac CPU, using two threads for XGBoost and PyTorch. The first kernel launch hit the sandbox’s local socket restriction, so execution used in-process IPython and preserved an executed notebook. PyTorch and XGBoost initially loaded different OpenMP libraries. The successful run used PyTorch’s copy for both. The final output cell also now takes a writable copy of its pandas Boolean mask before updating it. That compatibility fix affects candidate output preparation. The test calculations use their original code. The notebook ran with its optional candidate export disabled, so the earlier capacity release remains the release of record. ## Results in beds

MAE counts each bed of error equally. RMSE weights large misses more heavily. Positive paired differences mean the method’s MAE was higher than publisher ranking with the same population features.

| Method | Development MAE | Test MAE | Test RMSE | Test MAE difference versus ranked, with 95% interval |
| --- | ---: | ---: | ---: | --- |
| Publisher ranked with population | — | **136.44** | **316.89** | Reference |
| Out-of-fold-selected individual rule, shared date-based prediction | 139.22 | 137.47 | 321.12 | +1.03 [−1.16, +3.27] |
| Equal blend | 137.72 | 136.81 | 318.75 | +0.38 [−0.70, +1.51] |
| Inverse-error blend | 137.72 | 136.84 | 318.79 | +0.41 [−0.68, +1.55] |
| Learned fixed blend, selected on development | **137.71** | 136.81 | 318.75 | +0.38 [−0.70, +1.51] |
| Feedforward blend | 137.79 | 136.96 | 319.00 | +0.53 [−0.97, +2.13] |

The fixed blend improved on the individual rule chosen using out-of-fold fitting data by **0.65 beds** on test. Publisher ranking was the better individual rule on this test and had also won the earlier population-tier validation. The result provides no evidence of an improvement from facility-specific weights. At a nominal 90%, the fixed blend covered 89.9% of held-out counts with a median interval width of 460 beds. The publisher-ranked model covered 90.5% with a median width of 459 beds. Against the earlier cross-tier leader at 134.99 beds, the fixed blend was 1.82 beds worse with a paired 95% interval from −1.36 to +5.06. The default population tier and the blend were kept fixed for the comparison.
